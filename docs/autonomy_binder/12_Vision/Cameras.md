# Cameras

The Autonomy software utilizes the `CameraHandler` to initialize and stream physical cameras. The codebase supports two primary camera types: **ZED Stereoscopic Cameras** and **Basic Webcams**.

## The `ZEDCamera` Interface & `ZEDCam`
The primary "eyes" of the Mars Rover are Stereolabs ZED Cameras (typically the ZED 2i). The `ZEDCam` class (`src/vision/cameras/ZEDCam.cpp`) wraps the Stereolabs SDK (`sl::Camera`).

### Capabilities
1. **RGB Frames**: High-definition, low-latency color images.
2. **Depth Maps**: A `CV_32FC4` (or 16-bit float) matrix where every pixel contains an `(X, Y, Z)` coordinate relative to the camera lens.
3. **Spatial Mapping**: The ZED SDK builds a persistent 3D voxel mesh of the environment as the rover drives.
4. **Positional Tracking**: High-accuracy visual odometry. The camera uses its IMU and visual feature tracking to determine exactly how far and in what direction it has moved since startup.

### Memory Optimization
The ZED SDK runs heavily on the GPU (CUDA). To avoid expensive memory copies between the GPU and CPU RAM, `ZEDCam` supports outputting directly to `cv::cuda::GpuMat` instead of standard `cv::Mat` if the downstream algorithm (like YOLO) is running natively on the GPU.

### Hardware vs. Simulation
To make offline development seamless, the autonomy software implements a `SIMZEDCam` class. If `BUILD_SIM_MODE` is enabled, the code uses this class instead of `ZEDCam`. It connects to the `RoveSoSimulator` via WebRTC/PixelStreaming, pulling synthetic RGB and Depth frames generated by Unreal Engine, acting identically to the real hardware.

## The `BasicCamera` Interface
For non-depth tasks (like looking at a simple mechanism or streaming an underside view to the basestation), the software uses `BasicCam` (`src/vision/cameras/BasicCam.cpp`), which wraps standard USB webcams using OpenCV's `cv::VideoCapture`.
